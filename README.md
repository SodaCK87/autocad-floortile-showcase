# FLR — AutoCAD 地面磁磚鋪設規劃

[![static checks](https://github.com/SodaCK87/autocad-floortile-showcase/actions/workflows/ci.yml/badge.svg)](https://github.com/SodaCK87/autocad-floortile-showcase/actions/workflows/ci.yml)

把「這層樓的磁磚要從哪裡開始鋪」從師傅的經驗，變成圖面上算得出來、挑得到的方案。

在 AutoCAD 裡輸入 `FLR`、框選房間，它把上千種起鋪位置各評估一次：

1. 依你選的目標（**最少刀**／**最少廢料**／**邊磚最寬且左右對稱**）列出前幾名
2. 選一個進即時預覽，`W`/`A`/`S`/`D` 微調、數字鍵換方案
3. 確定後把磚、裁切尺寸標註、用量統計表與切割清單 CSV 一次畫進圖裡

![成圖與統計表](docs/images/result.png)

> **產出方式：本專案是與 Anthropic 的 Claude（Claude Code）協作開發的。**
> 需求界定、技術取捨與驗收由我把關，Claude 參與實作、測試撰寫與文件整理。
> 文件裡的每一組數字都來自實機量測，不是估算——包括那些**推翻我自己判斷**的量測結果。

## 這個 repo 是什麼

**展示用的節錄，不是完整的外掛。** 完整專案 12,532 行（不計空白行），其中 UI、即時預覽與繪圖
那半需要 AutoCAD 才跑得起來。這裡挑出**幾何與最佳化核心**——它完全不呼叫 AutoCAD API
（沒有 `entmake`、`ssget`、`vla-*`、`setvar`，只有 `princ` 印訊息），所以整份邏輯進得了無頭斷言。

| 檔案 | 行數 | 在做什麼 |
| --- | ---: | --- |
| [`src/FLR_Core.lsp`](src/FLR_Core.lsp) | 2,106 | 幾何與最佳化核心：多邊形裁剪、面積、形狀判定、條帶量測、尺寸分群、網格與交丁、候選集與排序、一維排料 |
| [`tests/FLR_Tests.lsp`](tests/FLR_Tests.lsp) | 1,917 | 上面那一份的 596 條斷言 |
| [`tools/FLR_NestLP.py`](tools/FLR_NestLP.py) | 120 | 排料最佳性檢查：Gilmore-Gomory 欄生成算 LP 下界，跟核心的 FFD 比（見[決策 3](docs/DECISIONS.md#d3)） |

- **不在這裡的**：DCL 對話框、`grread` 即時預覽、`entmake` 繪圖與 AutoCAD 表格物件、安裝 bundle、
  GUI 自動化測試工具，以及 33 頁的操作說明書與它的產生器——都要 AutoCAD，也不公開。
  完整專案的程式碼需要閱覽請[聯絡索取](#授權與索取)；文件裡的量測數據與這個節錄的測試不設限。
- **註解裡的內部參照一併留著**（`FLR:Evaluate`、`FLR:StatsOf`、TAD-01／FLR-14 這些缺陷編號、
  CHANGELOG 的版本節……），它們指向完整專案，在這個節錄裡查不到。刻意不改寫成通用說法：
  那些註解記的是**當時為什麼那樣決定**，把出處拿掉就只剩結論了。

## 跑測試

```powershell
.\tests\Run-CoreTests.ps1
```

- **結果**：**PASS 596 / FAIL 0**（2026-08-17 於 AutoCAD 2027 實跑）。
- **需要什麼**：本機有 AutoCAD，但**不必開它的視窗**——執行器走 `accoreconsole.exe`（無視窗核心）。
- **與完整專案一致**：同一份核心在完整專案裡跑出來的也是 596，一條不多一條不少——載不載入 UI 那一份不影響它。
- **完整專案的總量**：另有 UI 層可無頭驗證的 458 條與 GUI 全自動實測 53 項，合計 **1,054 條斷言**。

**這裡的 CI badge 不是「測試通過」。** 那 596 條要 `accoreconsole`，GitHub 的 runner 上沒有；
拿別的 Lisp 直譯器代跑會得到**隔一層的證據**——語意只要差一點，綠燈就是假的。所以 CI 只做在
runner 上真的驗得到的三件：

- **`.lsp` 是 UTF-8 無 BOM**——有 BOM 時 AutoCAD 的 `load` 會把它當成第一個字元，
  症狀是「載入失敗」而完全指不到編碼
- **括號平衡**——漏一個 `)` 會安靜地少定義最後幾支函式
- **沒有控制字元**

檢查器自己也被反向驗過：故意加一行不閉合的 `defun` 進去，它要抓得到才算數。

## 專案規模

- **語言與宿主**：AutoLISP，AutoCAD 2027（相容至舊版；圖面單位跟著現場走，現為 cm）
- **版本**：v1.4.7，核心 `FLR_Core` 0.9
- **主程式**：`.lsp` 10 檔 8,462 行（不計空白），另 PowerShell 15 檔 2,766 行、Python 2 檔 1,304 行
- **測試**：無頭斷言 1,054 條（核心 596 ＋ UI 458），另 GUI 全自動實測 53 項
- **量測工具**：六支探針——成本剖析、規模量測、前篩準度校準、排料最佳性、編碼、CSV 的 Excel COM 驗收
- **交付**：雙擊 `install.bat` 裝成 ApplicationPlugins bundle，不必 `APPLOAD`；33 頁操作說明書

> git 歷史只回溯到 2026-08-13——這個 repo 是從牆磚版分支出來後重開的，前期的提交不在裡面。
> 所以這裡不列 commit 數；逐版做了什麼在完整專案的 `CHANGELOG.md`。

## 五個值得講的決策

完整敘述與量測過程在 **[docs/DECISIONS.md](docs/DECISIONS.md)**，這裡只放結論。

| # | 決策 | 關鍵數字 |
| --- | --- | --- |
| [1](docs/DECISIONS.md#d1) | 不做 Region 布林，改成解析式裁剪 | 每片 0.055 ms，整層 5,500 片外推 300 ms → **不需要外部計算引擎**；連帶根除「統計算完了、圖卻沒畫出來」那類缺陷 |
| [2](docs/DECISIONS.md#d2) | 讓使用者選一個目標，不做加權總分 | 刀數／廢料／對稱三個量綱不同，權重只能憑空定。初版把違規設成共用第一順位，實測下「對稱」目標挑出的方案反而更不對稱（22.5 vs 預設目標的 20.8） |
| [3](docs/DECISIONS.md#d3) | 先量再改 | 每組候選 302 → **125 ms（−59%）**；事前懷疑的兩個熱點實測都是 **0 ms**；排料 FFD 六個實例全部等於 LP 下界，換算法收益 0 片 |
| [4](docs/DECISIONS.md#d4) | 我推翻過自己三次 | 準度取決於**凹形不是圖多大**（大圖上前篩反而中真值第 1）；給越多時間曾讓結果**變差**（4 秒優於 8 秒）；細掃收益 −38.9% 實為 **−3.6%** |
| [5](docs/DECISIONS.md#d5) | 沒有測試環境，就自己造一個 | 三層：抽離宿主 API 596 條、UI 可無頭部分 458 條、GUI 全自動 53 項。FLR-14：**534 條全綠，而即時預覽的按鍵一個都不會動**，只有像素差抓得到 |

## 其他畫面

**推薦清單。** 依選定的目標排序，每列印出刀數、違規片數與百分比、對稱誤差；
「母磚」欄只在選了「最少廢料」時才有數字（見[決策 2](docs/DECISIONS.md#d2)）：

![推薦清單](docs/images/picklist.png)

**主對話框。** 九個欄位各有出廠預設，旁邊有「說明」按鈕；圖層那兩顆按鈕會先關掉對話框
（DCL 開著時選不到圖元），做完帶著原有設定重新開啟：

![主對話框](docs/images/dialog.png)

`W`/`A`/`S`/`D` 微調、`+`/`-` 改步長、`T` 開關標註，單鍵即時不必按 Enter：

![即時預覽](docs/images/preview.png)

**用量統計表。** 分區小計與總計、邊料互補排料後的實需母磚、含耗損的建議叫料與箱數、
相異裁切尺寸清單，以及**起鋪基準與所有參數**——有這一格，這張圖才重現得出來：
